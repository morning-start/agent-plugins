# 需求清单（Requirements）

> Spec 模式起点。新增需求按此格式追加；变更/废弃标注状态。
> 每条需求保持与 plan / task 的链接（ref），防止漂移。

| id | title | priority | status | acceptance（验收标准） | ref |
|----|-------|----------|--------|------------------------|-----|
| REQ-001 | 示例：用户认证 | P0 | 待确认 | 用户可通过 OAuth 登录 | plan#P1 |

## 约定

- priority：P0（必须）/ P1（应该）/ P2（可以）/ P3（不做也行）
- status：待确认 / 已冻结 / 开发中 / 已完成 / 已排期 / 已拒绝
- 已知模糊点显式记录在备注（不脑补补全）
