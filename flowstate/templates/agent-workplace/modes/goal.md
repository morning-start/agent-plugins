# Loop 方略（Goal 模式，phase→loop / phase→task→loop）

> 适用：目标明确、需自动持续推进的长任务（连续修复测试、批量迁移、持续排查）。
> 核心：**设定完成条件 → 每轮自我评估 → 未达标继续、达标停止**——把单轮执行升级为
> 目标导向的多轮续跑。
> 别名：**loop agent**；在迭代中是 fst-iterate 的第二种方略（`phase→loop` 或
> `phase→task→loop`）。

## 定位（在迭代里的两种粒度）

| 粒度 | 链条 | 用法 |
|------|------|------|
| phase 级 | `phase→loop` | 整个 phase 按目标循环推进：设定该 phase 的完成条件，每轮逼近，达标才停 |
| task 级 | `phase→task→loop` | 单个任务按目标循环执行：任务自身设完成条件（如"全部测试通过且无 P0"），多轮收敛 |

**何时选它**：任务边界模糊、需要反复逼近目标、无人值守长跑时选 loop；
任务边界清晰、每步可验收时选 spec（见 `modes/spec.md`）。

## 流程

1. **定义目标**：`state/goal.md` 写入——
   - **完成条件**（可验证的终点，如"全部测试通过且无 P0 缺陷"）
   - **每轮工作边界**（每轮只做 bounded 工作，不一把梭）
   - **评估标准**（如何判断本轮达标/未达标）
2. **循环执行**：
   - 每轮结束：对照完成条件自我评估
   - 未达标 → 继续下一轮（更新 `state/goal.md` 的进度记录）
   - 达标 → 停止并汇报
3. **断点续跑**：每轮结束更新 `state/checkpoint.json`（已完成 / 当前进度），
   中断后可恢复

## 关键原则

- **先跑冒烟再继续**：每轮必须有可验证的进展信号，不能空转
- **独立复核**：长跑任务在收尾前让独立视角（subagent / 用户）审查 diff 与目标差距
- **勿过度工程**：评审只标影响正确性或既定需求的问题，风格问题不算

## 产物

`state/goal.md`（目标 + 自我评估记录）· `state/checkpoint.json`（断点续跑）
