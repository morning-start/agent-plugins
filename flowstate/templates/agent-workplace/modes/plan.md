# Plan 模式

> 适用：边界清晰、执行前需确认步骤的任务（中小功能、模块级重构、缺陷修复）。
> 核心：**先探索后计划，计划待确认才执行**——分离探索与执行，避免解决错问题。

## 流程

1. **探索（不改代码）**：读相关文件、理解现状、回答澄清问题
2. **写计划**：`docs/plan/PLAN.md`，按大阶段拆分为多个 **phase**，每个 phase 写明：
   - **要做什么**（目标与交付内容，关联需求 id）
   - **为什么做**（业务/技术理由）
   - **涉及文件 / 接口 / 验证方式**
3. **待确认**：计划写完**暂停**，等用户确认或编辑后再执行
4. **执行**：按 phase 逐批实现、逐批验证

## 何时跳过

- 改动能用一句话描述（改 typo、加日志、重命名变量）→ 直接做，不进 Plan

## 产物

`docs/plan/PLAN.md`（模板见 `modes/plan.md` 本文件约定；一个迭代一份，完成后归入
`docs/decisions.md` 或由用户决定是否提升到正式 `docs/`）
