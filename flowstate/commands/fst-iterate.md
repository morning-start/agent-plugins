# /fst-iterate — 迭代循环

启动 flowstate 迭代开发流程（N4 开发 / N8 持续迭代）。加载并遵循 `skills/fst-iterate/SKILL.md`。

## 步骤

1. **写 docs/plan**（分 phase）：按大阶段拆分（基础层 → 核心流程 → 交互/外围 → 打磨/上线准备），每 phase 写清"要做什么 / 为什么做"
2. **细化 docs/task**（分批）：按内聚程度（同模块/同层）与实现顺序（先依赖后上层）分批，批次间递进有序、每批可独立验证
3. **按批实现**（Git 分支开发，F4.2）：
   - 一个功能/变更单 = 一个分支（`feat/CR-001`），修复走 `fix/<bugslug>`
   - 一批一验（构建/冒烟），提交信息带变更单 id
4. **维护技术债清单**（schema 5.6）：登记妥协实现、原因、偿还迭代
5. **迭代末回顾**（schema 5.7）：交付统计 / 变更统计 / 度量（完成率、返工率、需求池积压）/ 风险与技术债 / 下轮建议
6. **下轮排期**：确认下轮迭代范围 → 回到第 1 步（N8→N4 持续迭代闭环）

## 规则

- 不写 plan/task 不动代码
- 任务不分批不实现（一批一验）
- 未确认需求只做骨架开发（骨架须过冒烟）
- 变更单未归档不得开新分支

## 下一步

迭代中变更 → `/fst-change`；验收 → `/fst-review`；回顾完成 + 下轮范围确定 → 回到本命令（闭环）。
