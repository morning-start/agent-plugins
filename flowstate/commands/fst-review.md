# /fst-review — 验收审查

启动 flowstate 验收流程（N6 测试 / N7 灰度）。加载并遵循 `skills/fst-review/SKILL.md`。

## 步骤

1. **变更针对性测试**：针对每次改动点 + 关联影响点（来自 fst-change 影响评估清单）
2. **高频回归测试**：回归核心主干流程（立项→开发→验收→上线的关键路径）
3. **骨架冒烟测试**：未确认需求的骨架必须通过冒烟；不做深度细节测试、不纳入交付验收
4. **DoD 核销**（迭代验收 Checklist，schema 5.4）：逐项核销，全部 ✅ 才可进入灰度
   - 功能完成（含骨架冒烟）/ 变更针对性测试 / 核心回归 / 文档同步 / 变更归档
5. **灰度方案 + 放量决策**：
   - 小流量比例、监控指标、回滚预案
   - 门槛：核心通过率 ≥ 99%、错误率 < 0.5%、无 P0、灰度反馈归入需求池
   - 用户确认放量/全量；不达标 → 回滚
6. **产出**：测试报告、回归结果、缺陷清单；反馈汇总标记遗漏需求 → 需求池

## 规则

- DoD 未逐项核销 → 不得合并/上线
- 回归未通过 → 不得进入灰度
- 灰度指标不达标 → 不得全量（回滚）

## 下一步

验收通过 → 灰度 → 全量 → `/fst-iterate` 回顾闭环（N8）；迭代中变更 → `/fst-change`。
