# /fst-change — 变更管控

启动 flowstate 变更管控流程（N5 变更 / N9 紧急通道）。加载并遵循 `skills/fst-change/SKILL.md`。

## 步骤

1. **记录需求原文**（立即，不改代码）：变更内容、提出人、渠道（口头/IM/邮件）
2. **建议变更分级**（AI 建议 + 用户确认）：
   - 轻微（文案/状态微调）→ 当前迭代直接修复
   - 中度（规则微调/次要细节）→ 记录存档、评估工时、本轮收尾或下轮实现
   - 重大（核心流程/结构重构）→ **暂停开发**，重新评估范围/工期/成本，二次评审后重启
   - 紧急（线上事故）→ Hotfix 直通车（见第 5 步）
3. **影响评估**：是否改库 / 是否重构 / 影响旧功能 / 工时估算 / 返工量
4. **审批 + 排期 + 归档**：重大变更人工审批；生成变更申请单（schema 5.3）
5. **紧急通道（Hotfix）**：先修后补单，24h 内补录变更申请单 + 影响评估 + 复盘
6. **落地 + 同步**：变更落地后同步更新 PRD/设计文档；一个变更单 = 一个功能分支

## 规则

- 无变更单不修改代码（先记录原文）
- 变更单未归档 + 未排期 → 不得开分支、不得动代码
- 重大变更必须人工审批后重启开发
