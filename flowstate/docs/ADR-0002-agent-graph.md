# ADR-0002 — Agent 图编排决策：流程 = 可执行状态图

- **状态**: Accepted（已接受）
- **日期**: 2026-08-08
- **背景**: 初版文档把流程写成线性阶段描述（F1→F9），但真实项目里流程
  有回环（变更管控）、分支（变更分级路由）、人工闸门（必须人确认的节点）、
  断点恢复（迭代中断）等需求。纯线性文档无法表达这些控制流，开发时容易
  靠人脑脑补、运行时不可路由、中断后只能从头走。

## 决策

将 flowstate 的全流程建模为**一张可执行的状态图（State Graph）**，而非线性文档：

- **节点（Node）** = 流程环节：F1~F9 映射为 N1~N9，每节点持有输入、产出物、DoD。
- **边（Edge）** = 流转条件：DoD 核销是边上的守卫条件（guard），未核销不能前进。
- **条件边（Conditional Edge）** = 路由决策：变更分级（轻微/中度→回 N4，重大→回 N3）、
  灰度达标→全量 / 不达标→回滚回 N6。
- **循环（Loop）** = 变更回环（N4→N5→N4）、迭代闭环（N8→N4）、Hotfix 短路（→N9→N6）。
- **人工闸门（HITL）** = 必须暂停等人确认的节点（底线冻结、范围签署、变更分级、
  重大审批、放量决策、DoD 核销）。
- **检查点（Checkpoint）** = 节点完成即保存状态（产出物 + 流转记录），断点续跑。
- **并行（Parallel）** = 多张变更单可并行评估影响。

完整图见 `docs/PRD.md` §7.8（mermaid）。

**承载方式（默认）**：图为"逻辑蓝图"，由 skills 逐节点实现（自研轻量状态机，
纯 skills 驱动，适合 Claude Code / pi 的 skills-only 模型）；Checkpoint 落在
产出物文件（docs/plan、docs/task、变更单等）上。是否对接 LangGraph 等外部
编排框架留待实现期评估（PRD §十一-5）。

## 后果

- 流程控制流（回环/分支/闸门/恢复）显式化，不依赖人脑。
- 每个 DoD 判据成为可校验的门禁，为自动化流转打基础。
- HITL 显式化：AI 不会越权做"只允许人做"的决策（见 PRD §2.2）。
- skills 落地时按节点粒度拆分，与图一一对应，便于测试与调试。

## 备选方案

- 纯线性文档（否决：无法表达回环/分支/闸门，开发时靠脑补）。
- 直接引入 LangGraph 等外部框架（备选：支持 Checkpoint/HITL/并行开箱即用，
  但引入运行时依赖，与 skills-only 的多端模型（Claude Code / pi / opencode）
  集成成本高；默认不选，留待实现期评估）。
