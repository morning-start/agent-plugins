## 每技能详情

### fst-init（立项初始化：N1~N3）

- **触发**：新项目启动、需求模糊、用户说"做个 X / 帮我想想这个项目"
- **输入**：用户原始构想（可能只有一句话）
- **AI 动作**：
  - 访谈 3 核心底线（一次一问，不脑补）；标记未知/模糊场景为「待确认需求」
  - 需求分层（刚性核心/弹性细节/临时新增）→ 生成需求分层清单草稿
  - 生成迭代范围说明书草稿、风险清单
  - 方案设计：主干冻结 + 柔性预留（可配置化/参数化/状态预留）
- **人工动作**：确认 3 底线、签署范围说明书、评审柔性 PRD
- **产出物（schema）**：5.1 需求分层清单、5.2 迭代范围说明书、5.5 风险清单
- **关联最佳实践**：流程框架（N1~N3 节点，见 `references/flow-graph.md`）
- **DoD**：3 底线书面确认 → 范围签署 → 柔性 PRD 通过

### fst-change（变更管控：N5 + N9）

- **触发**：任何新需求/需求改动（口头、IM、邮件）、线上事故
- **输入**：需求原文、变更提出人/渠道
- **AI 动作**：
  - 立即记录需求原文（防口头需求无痕消失）
  - 建议变更分级：轻微（当前迭代修）/ 中度（记录+评估+排期）/ 重大（暂停开发+重新评估）/ 紧急（Hotfix 直通）
  - 生成变更影响评估草稿（是否改库/重构/影响旧功能/工时）
  - 紧急通道：先修后补单，24h 内补录
- **人工动作**：确认变更分级、重大变更审批、排期确认
- **产出物（schema）**：5.3 变更申请单
- **关联最佳实践**：先探索后计划（内部方法，评估待确认后执行）
- **DoD**：变更单归档 + 已排期（未归档不得改动代码）

### fst-review（验收审查：N6~N7）

- **触发**：迭代开发完成 / 变更落地后 / 准备上线
- **输入**：可运行功能、docs/task 状态、变更记录
- **AI 动作**：
  - 变更针对性测试（改动点 + 关联影响点）
  - 高频回归测试（核心主干流程）；骨架冒烟测试
  - 生成灰度方案（流量比例、监控指标、回滚预案），汇总灰度反馈
- **人工动作**：DoD 逐项核销、灰度放量决策、全量上线决策
- **产出物（schema）**：5.4 迭代验收 Checklist
- **关联最佳实践**：DoD 核销清单（schema 5.4 逐项勾选核销）
- **DoD**：核心回归通过 + 变更点测试通过 → 灰度达标 → 全量

### fst-iterate（迭代循环：N4 + N8）

- **触发**：迭代开始、迭代结束回顾、新迭代排期
- **输入**：柔性 PRD、迭代范围说明书、需求池
- **AI 动作**：
  - 先盘点本轮需求（REQ-xxx + CR-xxx 变更单 + 需求池条目）→ 按需求特征选方略 → 用户确认
  - 开发前写 docs/plan（分 phase：要做什么/为什么做/声明方略 spec|loop|graph）→ 细化 docs/task（分批：内聚+顺序；spec 方略下任务带验收标准）
  - 按方略实现（spec 逐项核销 / loop 目标循环自评 / graph deps 拓扑推进）；一批一验（构建/冒烟）；按功能开 Git 分支（F4.2：一个变更单一个分支）
  - 维护技术债清单；迭代末生成回顾报告（度量/变更统计/风险）
  - 需求池优先级排序建议
- **人工动作**：**确认方略选型**、确认 phase/批次划分、确认下轮迭代范围
- **产出物（schema）**：5.6 技术债清单、5.7 迭代回顾报告、5.8 docs/plan（含 strategy 字段）、5.9 docs/task（含 acceptance 字段）
- **关联最佳实践**：由 `fst-mode-router` 选择 Spec（默认，任务带验收标准核销）/
  Loop（迭代闭环 N8→N4）/Graph（依赖图）/Todo（简单 diff）。
- **DoD**：DoD 全部核销 → 回顾完成 + 下轮范围确定

## Git 分支适配（F4.2）归属

- F4.2 属于 **fst-iterate**（N4 迭代开发的执行指引的一部分）
- 变更单=分支的规则联动 fst-change（N5）——跨技能衔接点，写入 fst-iterate 正文并引用 fst-change
