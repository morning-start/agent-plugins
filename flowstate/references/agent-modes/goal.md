# Loop 模式（目标循环）

> 定位：设定**可验证的完成条件**，每轮工作后自我评估，未达标继续、达标停止——
> 把单次执行升级为**目标导向的多轮续跑**。适合目标明确、边界模糊、需反复逼近且可无人值守的长任务。

## 是什么（本质）

不预先规划到每一步，而是定义一个**可验证的终点**（完成条件）；每轮只做 bounded（有明确边界）的工作，
轮末对照完成条件自我评估：未达标 → 继续下一轮；达标 → 停止并汇报。
核心是「目标闭环」，而不是「逐步清单」。

## 何时选用

- 目标明确但边界模糊，需反复逼近（连续修测试、批量迁移、持续排查）
- 可无人值守自动长跑

**反例**：每步可验收 → 用 **Spec 模式**；依赖复杂、可并行 → 用 **Graph 模式**。

## Iron Law

```
NO SIGNAL, NO NEXT ROUND
```

- 每轮必须有**可验证的进展信号**（构建 / 冒烟 / 测试），不能空转
- 未达标不得假装达标停止；达标必须停止汇报，不无限续跑
- 完成条件必须是**可验证的终点**（「全部测试通过且无 P0 缺陷」），不是「尽量做好」

## 执行步骤

1. **定义目标**：写出——
   - **完成条件**（可验证的终点）
   - **每轮工作边界**（每轮只做 bounded 工作，不一把梭）
   - **评估标准**（如何判断本轮达标 / 未达标）
2. **循环执行**：每轮结束对照完成条件自我评估；未达标 → 更新进度后继续下一轮；达标 → 停止并汇报
3. **断点续跑**：每轮记录进度，中断后可恢复（不在达标前丢失上下文）

## 产物

**目标状态记录**：目标定义（完成条件 / 每轮边界 / 评估标准）+ 进度记录（每轮做了什么、达标与否）+ 结束判定（何时达标、证据）。

## 与其他模式的关系

- 与 **Spec**：spec 每步可验收（边界清晰）；goal 目标循环（边界模糊、需逼近）
- 与 **Graph**：goal 适合「一条线逼近目标」，graph 适合「多分支并行编排」
- 与 **Todo**：todo 是「不用想就能做」，goal 是「每次只做 bounded 的一小步、持续逼近」
