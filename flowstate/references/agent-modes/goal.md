# Loop 模式（目标循环）

> **文件名说明**：本文件 `goal.md` 是历史遗留名；模式的**策略名与 `strategy` 字段均为 `loop`**
> （正式策略 spec / loop / graph 之一）。运行时状态记录在 `state/goal.md`，勿与本模式定义混淆。
>
> **一句话**：设可验证的完成条件，每轮做 bounded 工作并自评，未达标继续、达标停止——
> 把单次执行升级为**目标导向的多轮续跑**，适合可无人值守的长任务。

## 职责边界

| | 说明 |
|---|---|
| **负责** | 定义可验证的完成条件、每轮工作边界（bounded）、评估标准；每轮执行 bounded 工作并自我评估；达标即停并汇报；断点续跑 |
| **不负责** | 预先规划到每一步（spec 的逐项核销）、依赖图编排（Graph）、单点直做（Todo）、替用户做「该不该停」的越权判断 |
| **何时转交** | 目标边界逐渐清晰、可逐项验收 → 转 **Spec**；出现多依赖可并行 → 转 **Graph**；单点小改 → 转 **Todo** |

## 触发

**触发（Use when）**——满足任一：

- 目标明确但边界模糊，需反复逼近（连续修测试、批量迁移、持续排查）
- 可无人值守自动长跑
- 每轮有可验证的进展信号（构建 / 冒烟 / 测试），能自评达标与否

**明确不触发（Do NOT use when）**——满足任一即退出：

- 每步可验收、边界清晰 → 转 **Spec**
- 依赖复杂、可并行 → 转 **Graph**
- 一句话能说清 diff → 转 **Todo**
- 完成条件不可验证 / 每轮无进展信号 → 先定义信号，否则不要用 Loop（会空转）
- 需要人在每轮都确认决策 → 这是 HITL 密集流程，不适合无人值守长跑，转 **Spec**

## Iron Law

```
NO SIGNAL, NO NEXT ROUND
```

- 每轮必须有**可验证的进展信号**（构建 / 冒烟 / 测试），不能空转
- 未达标不得假装达标停止；达标必须停止汇报，不无限续跑
- 完成条件必须是**可验证的终点**（「全部测试通过且无 P0 缺陷」），不是「尽量做好」
- **证据门**：每轮自评「达标 / 未达标」必须有**本轮刚跑过**的信号输出；无输出 = 本轮无效

## 流程

> 门控：每轮结束**暂停自评**——未达标才允许下一轮，达标立即停止。

1. **定义目标**：写出——
   - **完成条件**（可验证的终点，断言式）
   - **每轮工作边界**（bounded：每轮只做**有限、可验证**的工作，不一把梭）
   - **评估标准**（如何判断本轮达标 / 未达标——需要什么信号、信号在哪条命令）
2. **循环执行**：每轮结束对照完成条件自我评估——
   - 未达标 → 更新进度后继续下一轮（每轮记录：做了什么 / 信号输出 / 达标与否）
   - 达标 → **立即停止**并汇报（附达标证据）
3. **断点续跑**：每轮记录进度，中断后可恢复（不在达标前丢失上下文）

## 产物

**目标状态记录**：目标定义（完成条件 / 每轮边界 / 评估标准）+ 进度记录（每轮做了什么、信号输出、达标与否）+ 结束判定（何时达标、证据）。

## 自我怀疑（Rationalizations to Reject）

| 借口 | 现实 |
|------|------|
| "这轮没信号，但我感觉快了" | 无进展信号 = 空转 → 停，先补可验证信号 |
| "再跑一轮就差不多了" | 完成条件是终点不是感觉；未达标可以继续，达标必须停 |
| "目标不太清楚，但跑起来就明白了" | 完成条件不可验证 → 先定义终点，否则每轮都无法判定 |
| "我多跑几轮顺便做点别的" | 超出目标边界的改动 → 转模式或另开目标 |
| "已经达标了，但再多做一点更完美" | 达标即停是铁律；想锦上添花 → 另开目标或转 Spec 逐项验收 |
| "上次的测试结果应该还算数" | 每轮自评必须用本轮刚跑过的信号；旧结果不构成证据 |

## 红旗（Red Flags - STOP）

- 连续两轮无进展信号 → 停，怀疑信号定义或目标不可达
- 计划不达标也硬停、或达标了还想续跑 → 停，回归完成条件
- 完成条件不可验证 / 每轮无法自评 → 停，先定义信号
- 想无人值守但缺少「达标即停」的守门机制 → 停，补守门（每轮自评 + 证据门）
- 一轮做了远超 bounded 范围的工作 → 停，回退到小步快跑

## 验证（Verification）

- [ ] 完成条件可验证（断言式终点）
- [ ] 每轮工作边界明确（bounded，不一把梭）
- [ ] 每轮均有进展信号，且逐轮自评达标与否
- [ ] 达标即停并有证据；未达标未假停
- [ ] 断点续跑信息已记录（中断后可恢复）

## 与其他模式的关系

- **→ Spec**：边界逐渐清晰、可逐项验收 → 转回
- **→ Graph**：出现多依赖可并行 → 升级
- **→ Todo**：单点小改 → 降级
- 与 **Graph**：Loop 适合「一条线逼近目标」，Graph 适合「多分支并行编排」
- 目标循环中发现的单个验收清晰子任务，可临时用 Spec/Todo 核销后再继续循环
