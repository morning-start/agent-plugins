# Graph 模式（依赖图编排）

> 定位：把工作建模为**带依赖关系的节点图**，按拓扑顺序推进，无依赖的节点并行执行。
> 适合依赖复杂、跨模块、可并行、需显式控制先后顺序的任务；是四种 mode 中「编排」粒度最重的一种。

## 是什么（本质）

把一批工作拆成**节点**（任务 / 子步骤），用**依赖边（deps）**标明先后关系，每个节点带**验收标准（DoD）**；
执行时按拓扑顺序推进——无前置依赖的先做、互不依赖的并行做；节点完成 = 验收核销，未核销不得进入下游。

## 何时选用

- 依赖复杂、跨多个模块或分层
- 多个任务可并行，需要显式控制先后顺序
- 大重构、多变更联动等「牵一发动全身」的场景

**反例**：每步独立、先后无所谓 → 用 **Spec 模式**；单条线反复逼近目标 → 用 **Goal 模式**。

## Iron Law

```
NO DoD, NO DOWNSTREAM
```

- 节点未核销（DoD 未过）→ 不得进入依赖它的下游节点
- 无前置依赖的节点先行；无相互依赖的节点**可并行**（不要无谓串行）
- 节点失败 → 回退到依赖它的上游节点修复，**不整体重跑**

## 执行步骤

1. **建图**：把工作拆为节点（任务或子步骤），用 `deps` 字段标依赖边；每节点标注验收标准
2. **拓扑执行**：按依赖顺序推进——无前置依赖的节点先行；互不依赖的节点并行
3. **每节点核销**：节点完成 = 该节点验收标准核销（DoD 守卫），未核销不得进入下游
4. **失败回退**：节点失败 → 回退到依赖它的上游节点修复；发现新变更 → 走变更管控，不整体重跑
5. **断点续跑**：每节点完成即记录进度，中断后可恢复

## 产物

- **任务依赖图**：节点（任务/子步骤）+ 依赖边（`deps`）+ 每节点验收标准（DoD）
- **拓扑进度记录**：当前完成到哪、还有哪些节点未核销（支持断点续跑）
- 可选：图可视化（mermaid / 依赖列表）

## 与其他模式的关系

- 与 **Spec**：spec 定义「每个节点做到什么算完成」，graph 定义「节点之间怎么走」——graph 的节点通常用 spec 的验收方式去核销
- 与 **Goal**：goal 适合「一条线逼近目标」，graph 适合「多分支并行编排」
- 与 **Todo**：todo 是「不用想就能做」，graph 是「必须先想清依赖关系才能做」
