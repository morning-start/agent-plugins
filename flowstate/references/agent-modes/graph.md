# Graph 模式（依赖图编排）

> **一句话**：把工作建模为**带依赖关系的节点图**，按拓扑顺序推进，无依赖的节点并行执行。
> 是四种 mode 中「编排」粒度最重的一种，适合依赖复杂、跨模块、可并行的任务。

## 职责边界

| | 说明 |
|---|---|
| **负责** | 建节点依赖图（节点 + deps + 每节点 DoD）；按拓扑顺序推进并显式控制并行；每节点 DoD 核销；失败回退到上游修复；断点续跑 |
| **不负责** | 单点直做（Todo）、逐项验收的常规开发（Spec）、单线逼近目标（Loop）、跨节点的人审决策（HITL 归人） |
| **何时转交** | 依赖关系理清后可逐节点验收 → 每节点内用 **Spec** 核销；出现需反复逼近的子问题 → 该子问题转 **Loop**；节点内单点小改 → 用 **Todo** 直做 |

## 触发

**触发（Use when）**——满足任一：

- 依赖复杂、跨多个模块或分层
- 多个任务可并行，需要显式控制先后顺序
- 大重构、多变更联动等「牵一发动全身」的场景
- 已识别出明确依赖关系（建表 → 接口 → 页面）且可画成图

**明确不触发（Do NOT use when）**——满足任一即退出：

- 每步独立、先后无所谓 → 转 **Spec**
- 单条线反复逼近目标 → 转 **Loop**
- 一句话能说清 diff → 转 **Todo**
- 依赖关系还没想清就硬画图 → 先澄清，否则图是错的

## Iron Law

```
NO DoD, NO DOWNSTREAM
```

- 节点未核销（DoD 未过）→ 不得进入依赖它的下游节点
- 无前置依赖的节点先行；无相互依赖的节点**可并行**（不要无谓串行）
- 节点失败 → 回退到依赖它的上游节点修复，**不整体重跑**
- 依赖方向单向、无环：两节点互相依赖 → 应合并为一个节点
- **节点粒度**：一个节点 = 能在一次聚焦工作中实现 + 测试 + 验证的大小；过大的节点应再拆分
- **证据门**：声称节点 DoD 核销前必须有**本消息内刚跑过**的验证输出；未跑过 = 未核销

## 流程

> 门控：每节点完成**暂停核销 DoD**，未核销不得进入下游；关键合并点可设人审闸门。

1. **建图**：把工作拆为节点（任务或子步骤），用 `deps` 字段标依赖边；每节点标注——
   - **验收标准（DoD）**：断言式，可测试
   - **验证步骤**：跑什么命令证明 DoD（如 `npm test`、`build`、冒烟）
   - 依赖单向无环；两节点互相依赖 → 合并为一个节点
2. **拓扑执行**：按依赖顺序推进——无前置依赖的节点先行；互不依赖的节点并行（不要无谓串行）
3. **每节点核销（证据门）**：节点完成 = 该节点 DoD 核销——跑验证步骤、**读到输出**确认通过；未核销不得进入下游
4. **失败回退**：节点失败 → 回退到依赖它的上游节点修复；发现新变更 → 走变更管控，不整体重跑
5. **断点续跑**：每节点完成即记录进度，中断后可恢复

## 产物

- **任务依赖图**：节点（任务/子步骤）+ 依赖边（`deps`）+ 每节点验收标准（DoD）+ 验证步骤
- **拓扑进度记录**：当前完成到哪、还有哪些节点未核销（支持断点续跑）
- 可选：图可视化（mermaid / 依赖列表）

## 自我怀疑（Rationalizations to Reject）

| 借口 | 现实 |
|------|------|
| "这些任务其实可以并行，先一个个做" | 无谓串行浪费并行度 → 建图显式标并行 |
| "先做 X，不管依赖关系" | 未核销上游就进下游 = 违反 Iron Law → 回退 |
| "这个节点不用验收，先推下去" | 无 DoD 的节点会拖垮下游 → 补验收标准 |
| "依赖有点乱，但先将就画" | 图错了执行全错 → 先澄清依赖再建图 |
| "节点太大了，但拆了麻烦" | 过大的节点无法一次验证 → 拆小，否则核销不可信 |
| "这个节点跑过测试了，不用再看输出" | 核销必须本消息内跑过验证并读输出；旧结果不构成证据 |

## 红旗（Red Flags - STOP）

- 出现依赖环（A→B→A）→ 停，合并节点或重构依赖
- 打算在未核销上游节点时进入下游 → 停，回退
- 所有节点无 DoD → 停，补验收标准
- 想整体重跑以「修复」一个节点 → 停，应回退到上游节点定点修复
- 依赖关系不明却已开始画图执行 → 停，先澄清
- 声称节点核销但本消息内没跑过验证 → 停，跑验证再看输出

## 验证（Verification）

- [ ] 依赖图单向无环，`deps` 标注完整
- [ ] 每个节点都有验收标准（DoD，断言式）+ 验证步骤
- [ ] 每个节点粒度适中（能一次实现 + 测试 + 验证）
- [ ] 拓扑顺序正确：无前置依赖先行、互不依赖并行
- [ ] 所有节点 DoD 已核销（本消息内有验证输出）；未核销节点未进入下游
- [ ] 失败节点已回退到上游定点修复，未整体重跑
- [ ] 断点续跑信息已记录

## 与其他模式的关系

- **→ Spec**：图里每个节点完成 = 该节点 DoD 核销，通常用 **Spec** 的验收方式核销
- **→ Loop**：图中某个节点需反复逼近、边界模糊 → 该节点内部转 **Loop**
- **→ Todo**：图里单点小改的子步骤 → 用 **Todo** 直做
- 与 **Spec**：spec 定义「每个节点做到什么算完成」，graph 定义「节点之间怎么走」
- 与 **Loop**：graph 适合「多分支并行编排」，loop 适合「一条线逼近目标」
