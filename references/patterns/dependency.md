# 依赖管理参考

> **阶段 A** — MoonBit 包仓库（mooncakes.io）尚在发展，此文档作为知识库承载依赖更新策略、许可证合规清单和漏洞追踪流程。待 mooncakes.io 稳定后升级为 `moonbit-dependency` 技能。

## 依赖管理原则

1. **精确版本** — 使用精确版本号而非范围版本（`0.3.0` 而非 `^0.3.0`），确保构建可重复
2. **最小依赖** — 只引入满足需求的最小依赖集，避免传递依赖膨胀
3. **及时更新** — 定期检查依赖更新，避免积累过时依赖导致升级困难
4. **安全优先** — 依赖的已知漏洞（CVE）应优先处理

## moon.mod 依赖声明

MoonBit 项目的依赖在 `moon.mod` 文件中声明：

```json
{
  "name": "my-project",
  "version": "0.1.0",
  "deps": {
    "username/lib-a": "0.2.0",
    "username/lib-b": "1.5.0"
  }
}
```

### 依赖声明建议

- **lib 项目**：尽量少依赖，保持低耦合
- **cli 项目**：可接受合理数量的依赖
- **wasm/ffi 项目**：注意 FFI 依赖的平台兼容性

## 依赖更新策略

### 更新频率

| 依赖类型 | 更新频率 | 风险等级 |
|---------|---------|---------|
| 核心运行时依赖 | 每个发布周期检查 | 高 |
| 工具/开发依赖 | 每月检查 | 低 |
| 安全相关依赖 | 有 CVE 立即更新 | 紧急 |

### 更新流程

```bash
# 1. 列出当前依赖和版本
cat moon.mod | grep "deps" -A 10

# 2. 检查依赖变更
# 查阅每个依赖的 CHANGELOG 或 Release Notes

# 3. 更新 moon.mod 中的版本号

# 4. 验证更新后兼容性
moon check --warn-list +73
moon test --target native
moon info --target native && git diff --exit-code
```

### 依赖更新类型

| 变更类型 | 处理方式 | 说明 |
|---------|---------|------|
| **patch**（bug 修复） | 可直接更新 | 语义兼容，通常在安全更新时自动采纳 |
| **minor**（新功能） | 评估后更新 | 检查是否有破坏性变更或行为变化 |
| **major**（破坏性变更） | 分阶段升级 | 需要确认 API 迁移路径，可能涉及大量代码调整 |

## 许可证合规

### 许可证兼容性矩阵

| 许可证 | 可被 MoonBit 项目使用 | 使用条件 |
|--------|---------------------|---------|
| MIT | ✅ | 保留版权声明 |
| Apache 2.0 | ✅ | 保留版权声明和修改说明 |
| BSD-2/3-Clause | ✅ | 保留版权声明 |
| LGPL | ✅（动态链接） | 可闭源链接 |
| GPL | ⚠️ 谨慎 | 可能传染整个项目 |
| MPL 2.0 | ✅ | 修改的文件需保留版权 |
| Unlicense / CC0 | ✅ | 无限制 |

### 合规检查清单

- [ ] 所有依赖的许可证已知并记录
- [ ] 许可证兼容项目预期发布方式（开源/闭源）
- [ ] 依赖的版权声明已在项目中存档（如有要求）
- [ ] 依赖的许可证不在项目禁止列表上

## 漏洞追踪

### CVE 检查流程

```bash
# 手动检查依赖的 CVE（阶段 A：mooncakes 尚无自动扫描）
# 1. 列出所有依赖及其版本
# 2. 查阅每个依赖的 GitHub Advisory / Release Notes
# 3. 在 NVD (https://nvd.nist.gov) 搜索相关 CVE

# 自动检查（当 moon-audit 支持时）
# moon-audit deps .   # 暂未实现
```

### 漏洞响应

| CVSS 评分 | 严重度 | 响应时间 | 处理方式 |
|-----------|--------|---------|---------|
| 9.0-10.0 | 严重 | 24 小时内 | 立即修复或加补丁 |
| 7.0-8.9 | 高危 | 1 周内 | 安排修复 |
| 4.0-6.9 | 中危 | 下个发布周期 | 安排修复 |
| 0.1-3.9 | 低危 | 按计划 | 记录并跟踪 |

### 依赖安全最佳实践

1. 不在依赖中引入不必要的网络请求或文件系统权限
2. 审查依赖的 `moon.pkg` 中是否有意外暴露的 `pub` API
3. 警惕"微小但流行"的依赖（typofix 风险）
4. 定期运行 `moon-audit pipeline .`（如已安装）
